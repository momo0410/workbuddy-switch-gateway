## 关于再分发授权的询问

你好，我是 [momo0410](https://github.com/momo0410)。

我把你的 **workbuddy2api** 与另一个开源项目
[changexbc/workbuddy-switch](https://github.com/changexbc/workbuddy-switch)（MIT）
做了一次整合：把网关作为子进程托管在 workbuddy-switch 的桌面 GUI 里，
并新增了一个「兼容网关」页面（选端口、一键启停、看账号池状态）。

具体做法：
- 用 Go 把你的 `cmd/server` 编译成 `gateway.exe`
- 用 `build.rs` 把它 gzip 压缩后用 `include_bytes!` 编进主程序，
  运行时按内容指纹释放到 `~/.wb-switch/gateway/bin/`，这样只需分发一个 exe
- 账号侧：账号库变更时自动导出成你的 `auths/workbuddy-<uid>.json` 格式并同步
  （注意毫秒 ↔ 秒的换算）

开源整合过程里发现并修了几个问题，如果你觉得有价值我可以单独给你 PR：
1. **端口检测**：`TcpListener::bind` 试绑 `0.0.0.0`/`[::]` 在本机 Docker 转发
   端口时会**成功**，导致误判「端口空闲」，子进程随后绑定失败、
   而健康探测打到旧服务上报假成功。我改成「试绑 + 主动连接」双判定。
2. 健康探测增加身份校验（用 api_key 请求 `/status`，401 即认为不是自己的网关）。
